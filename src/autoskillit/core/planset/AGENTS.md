The IL-0 plan-set domain owns deterministic regex-only requirement extraction, allocation parsing, aggregate coverage, and verification; the server owns fetching and persistence. `plan_set_coverage` is an in-process server-side aggregate inspection, not a decision made by a child skill. Unsupported Markdown is recorded as a fail-closed marker, `text_digest` covers exact raw item spans rather than normalized text, and skills never open authority artifacts. Part commands are evidence only: the authority carries the hashed parts and coverage result. Its `state` is included in the canonical payload covered by the unkeyed integrity hash `authority_digest`; admission requires both a matching recomputed digest and `state == sealed`.

Recipe admission also requires server-held issuance provenance: the `PlanSetMaterializer` service held by `ToolContext` records each successful recipe bind's resolved root and digest by execution ID and authority path. Its default implementation is `DefaultPlanSetMaterializer`. Admission verifies the original caller path under that recorded root, then compares the verified digest with the issued digest. Standalone binds keep cwd-rooted containment and create no recipe record; audit inputs retain their invocation-cwd root.

Records remain in memory for the server process lifetime, including obsolete executions. Reinstalling an execution on the same context preserves them; fresh contexts, including fleet-side contexts, need their own successful recipe bind. This trusts the server process, its records, and the supplied root and its ancestors. The root is a path rather than a retained directory descriptor or bind-time inode identity, so replacing the root or its ancestors can change later resolution. The digest pin does not protect directory identity, and a sibling worktree does not establish OS-level isolation.
